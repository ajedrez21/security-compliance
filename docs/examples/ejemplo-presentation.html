CríticaExportación de todos los clientes sin autenticación ni autorizaciónsrc/server.js:29SEC-AUTHZ-001revisión del agente

Qué pasa: La ruta GET /api/export/all-customers devuelve id, name, email y tax_id de todos los clientes sin ningún control de acceso.

Flujo: GET /api/export/all-customers (sin credenciales) → handler anónimo → db.query SELECT sobre customers → respuesta JSON completa. No hay middleware global (app.use) ni guard por ruta; las demás rutas sí usan requireAuth, lo que confirma que es una omisión puntual y no una política global.

Riesgo: Exposición masiva de datos personales (email, identificador fiscal) a cualquier visitante.

Qué hacer: Agregar requireAuth y requireRole('admin') o una política equivalente; evaluar si la exportación debe existir y registrarla como evento auditable.

Evidencia: app.get('/api/export/all-customers', async (req, res) => {...}) sin requireAuth/requireRole

Análisis del agente de IA con flujo documentado; no verificado de forma independiente.

AltaConcatenación de req.query.name en una sentencia SQLsrc/server.js:17SEC-INPUT-001revisión del agente

Qué pasa: El parámetro name se concatena dentro de comillas simples en el SQL ejecutado por db.query sin parametrizar ni validar.

Flujo: GET /api/customers?name=… (usuario autenticado) → req.query.name → concatenación en 'sql' → db.query(sql). Control existente: solo autenticación; no hay validación ni parámetros.

Riesgo: Inyección SQL: lectura o modificación de datos con los privilegios de la cuenta de la aplicación.

Qué hacer: Usar db.query('SELECT id, name FROM customers WHERE name = $1', [req.query.name]).

Evidencia: const sql = "SELECT id, name FROM customers WHERE name = '" + req.query.name + "'";
